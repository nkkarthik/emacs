- 2026-06-18 =src/nsterm.m=: fix daemon hang after frame maximize (round 4).  Diagnosed on a live hung daemon (PID 21926, running the round-3 binary): =[NSApp modalWindow]= was *nil* and =send_appdefined= was *NO* — so round 3's modal-defer theory was wrong.  Real root cause: after a fullscreen/maximize transition =mainWindow= and =keyWindow= are both left nil, and the =NSApplicationDefined= stop-event we post (=windowNumber 0=) is never returned by =nextEventMatchingMask:= — it is dropped, so =[NSApp run]= loops on its 0.1 s timeout forever (event always nil; =send_appdefined= already NO, so round 3's re-post branch never fires).  Verified re-posting does *not* recover (freshly posted events drop the same way) but calling =[NSApp stop:]= directly does — a stuck client =(+ 40 2)= returned 42 immediately.  Fix: in =-run=, on a timeout with a stop-event still in flight (=send_appdefined == NO=, or the drain path captured at entry) and no modal window, set =last_appdefined_event_data= from the recorded =last_posted_appdefined_value= and call =[self stop:self]= directly instead of re-posting.  =drainAndStop= (entry =!send_appdefined=) keeps genuine =ns_select= waits blocking; timeout is 0.05 s while a stop is in flight, 0.5 s otherwise (fewer idle wakeups than round 3's flat 0.1 s).  Compiled clean.
